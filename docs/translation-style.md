# 翻譯風格指南

持續更新。翻譯時遇到的取捨、專有名詞表記、以及字庫缺口的處理原則都記在這裡。

## 語域

整體定在**偏文言、帶古日語翻譯腔**，不艱澀。題材是古事記神話，這個調性比
現代白話更合。

| 角色 | 自稱 | 對主角的稱呼 |
|---|---|---|
| 神明（天照、少名毘古那） | 吾 | 汝 |
| 村長、武人 | 我／在下 | U大人、閣下、汝 |
| 一般村民 | 我 | U大人、大哥哥 |
| 山賊、粗人 | 老子／我 | 汝、這廝 |

這不只是風格選擇，也是被字庫逼出來的：`你` `您` 都不在 JIS X 0208 內，
第二人稱只剩 `汝` `君` `爾`，白話根本寫不成。詳見下節。

## 字庫缺口的處理原則

JIS X 0208 是日文字集。拿 192 個中文最常用字測只缺 7 個（3%），
但缺口分布**極不平均**：文言／書面語幾乎無礙，**口語是重災區**。

`tools/jis.py` 會列出缺字並給建議，`tools/event.py verify` 會整批擋下。

### 疑問句

`嗎` 不存在。依句長與語氣分三種處理：

| 情境 | 寫法 | 例 |
|---|---|---|
| 短問句 | 「可否？」 | 可以嗎？→ 可否？ |
| 長問句 | 句尾用「乎？」 | 這是真的嗎？→ 此事當真乎？ |
| 反問、詰問 | 句尾用「邪？」 | 汝也要與我為敵邪？ |

`麼` 在字庫內，語氣較輕時仍可用（「是麼」「真的麼」）。

### 語尾助詞

`啊 喔 嗎 呢 吧 哪` 全缺，只剩 `呀` `嘛`。
依語氣改用文言助詞 **`也 / 矣 / 哉 / 夫 / 耳 / 焉`**，或整句改成直述。

### 字形選用：繁體優先

這是**繁體中文化**，所以規則是：

> **JIS X 0208 有繁體字形就用繁體，只有缺字時才退回日系新字體。**

下面那張替換表是「繁體缺字」的清單，不是偏好清單。除了表內那些字，
一律寫 `讓` 不寫 `譲`、`戰` 不寫 `戦`、`選擇` 不寫 `選択`、`龍宮` 不寫 `竜宮`。

同一個字混著寫，單看一行不會錯，連起來玩就很明顯。
`tools/consistency.py` 會整批掃出兩類問題：

1. **變體混用** —— 同一個字兩種寫法都出現，列出少數派的位置
2. **同原文多種譯法** —— 同一句日文被譯成不同結果

第 2 類對**句尾續段**（`になりました`、`なければな…` 這種跨訊息的片段）
會誤報，因為它們本來就接在不同的前文之後；其餘都該修。

劇情與 UI 全部譯完後還留著 7 項誤報，全是這類：

| 原文 | 兩種譯法 | 為什麼都對 |
|---|---|---|
| `いでください` | 來 / 曾 | 前者接「請稍後再」，後者接「最後之村熊」 |
| `になりました` | 成矣 / 矣 | 接在不同的前半句之後 |
| `なければな…` | 出去才行… / 才是… | 同上 |
| `の` | 個 / 者 | 單字片段，由引擎在執行期拼接 |
| `%sができあがりました` | %s打造完成了 / %s做好了 | 前者是鍛冶屋，後者是玉造 |
| `は` | 乃 / ， | 前者接氣候描述，後者接「已然離去」 |
| `逃げる` | 逃走 / 逃　走 | 兩個選單的排版節奏不同（一個夾全形空格） |

**不要為了消掉誤報而硬統一。** 這些是引擎在執行期拼接的片段，
譯法必須隨前後文走。

### 可直接替換成日系新字體的字

讀起來不影響，直接換：

```
產→産  查→査  錄→録  說→説  每→毎  內→内  姊→姉  溫→温
彥→彦  黃→黄  眾→衆  歷→歴  步→歩  淚→涙  黑→黒  增→増
絕→絶  擊→撃  鄉→郷  剝→剥  啟→啓  寬→寛  值→値  巢→巣
狀→状  綠→緑  沉→沈
```

> **`cp932` 不等於 JIS X 0208。** cp932 多收了 NEC 第 13 區與 NEC/IBM
> 擴充區約 400 字，這些字編碼得出來、但 DOS/V 字型沒有字模，畫面上是空白。
> 「黑」(0xEEEC) 就是這樣被抓到的。`tools/jis.py` 檢查的是 Shift-JIS 的
> lead byte，不是「cp932 能不能編碼」。

### UI 文字的額外約束

UI 字串是**就地覆寫**（`tools/patch.py`），與劇情的變長回寫不同，有三條硬限制：

1. **不可超過 `max_bytes`** —— 原字串到 NUL 為止的長度。超出就踩到下一筆資料。
2. **`%s` `%d` `%u` `%4d` `%-14s` `%6lu` 等格式符號必須原樣保留、順序不變**，
   個數也不能增減；引擎照順序填值。
3. **半形空白是版面對齊用的**，不是可有可無的裝飾。
   譯文字數變短時要補空白維持右對齊，例如
   `重装の鉄普及率        %3d％` → `重装鉄普及率          %3d％`（補 2 格）。

另外 `extracted/text/main_ui.tsv` 裡有約 90 筆的 offset 落在字串中段，
抽出來會帶一截亂碼前綴（如 `窰轜職業選択`、`痳村の方針`）。
這些要先往回找到前一個 NUL 之後的真實起點，再跳過前綴資料位元組，
只覆寫純日文那一段 —— 亂碼前綴是前一筆資料的尾巴，覆寫掉會壞檔。

#### 抽取門檻的陷阱

`tools/text.py` 的預設 `--min-chars 4` 會丟掉所有三個字元以內的字串，
而這款遊戲的**按鈕標籤、職業名、屬性名、地形名幾乎都只有 2–3 字**，
兩字詞還常夾一個半形空格撐滿按鈕（`確 認`、`は い`、`稲　作`）——
字元數剛好卡在門檻下。這一刀砍掉了約 250 條真正的 UI 文字，
包括整張通用對話框按鈕表（`MAIN.EXE 0x045110`）。

掃 UI 時一律用 `--min-chars 2`，再用「重算起點 + 比對已涵蓋範圍」的方式
找出漏網的：

```sh
.venv/bin/python tools/text.py game/KAMI/MAIN.EXE --start 0x40000 \
    --min-chars 2 --min-japanese 1 --out /tmp/rescan.tsv
```

門檻放寬後雜訊會變多（程式碼與圖形資料偶然解得出 Shift-JIS），
要人工剔除。**絕對不要翻的是假名輸入器的字候選表**
（`0x05251c` 起那串 `荏於下蛾翫亀乎験硬孜…`）——
那是按筆畫排好的候選字陣列，不是文字。

#### 固定間距的 record 表要按 stride 走，不能按 NUL 走

有幾張表的 record 是「名稱 + 數值」的固定長度結構，數值位元組不是 0，
往回找 NUL 會停在數值中間：

| 表 | 起點 | stride | 名稱欄 | 筆數 |
|---|---|---:|---:|---:|
| 術法 | `0x044470` | 16 | 11 | 48（第 49 筆 `宮沢りえ` 是彩蛋，未使用） |
| 人物初始值 | `0x04d174` | 33 | 15 | 150 |
| 地名 | `0x04be94` | 29 | 9 | 29 |

這三張一律用 `base + i * stride` 定位。曾經踩過的錯：人物 116 的 offset
少算一格（`0x04e067`），把前一筆的數值位元組 `0x38` 當成字串的 `8`，
抽出來是 `8オズマ`。

#### 中日同形就不要動

`海` `川` `沼` `山` `森` `村` `力` `運` `術` `金` `銅` `銀` 這類標籤，
以及 `%5u人`、`第%w部隊 `、`%8s %2d人(%s%d人)` 這種只含同形字的格式字串，
日文與中文寫法相同，**不必列進 TSV** —— 列了只是多一筆沒有差異的覆寫。

#### 道具名的「の」

道具名的 `の` 要不要譯成「之」，依序套用：

1. **古事記有固定名稱就照用**，不論有沒有「之」：`八遍醸みの酒` → 八鹽折之酒、
   `神度の剣` → 神度劍、`天の詔琴` → 天詔琴、`八尺の勾玉` → 八尺勾玉。
2. **修飾語是「天」就加「之」**：天之羽衣、天之石杖、天之横刀、天之土偶、
   天之破羽矢（`破羽` 照遊戲原字，不改成古事記的「波波」）。
3. **單字修飾語＋單字器物加「之」**：葛之弓、赤之鎧、鱗之衣、光之衣。
   但**組合本身已是常用詞就不加**：鐵劍、鐵鎧、皮鎧、皮服、桃實、椋實、蒲粉、
   龍涙、兎尾、蓮葉。
4. **成套的道具寫法一致**：三件土偶都加「之」——風之土偶、地之土偶、天之土偶。
5. **其他一律不加**：修飾語或器物有兩字以上時直接相連，如赤銅劍、黒鐵太刀、
   大蛇劍、銅短甲、銀腕環、伊邪那岐矛。

`皮の服` 譯「皮服」不譯「皮衣」：原文刻意分 `服`（皮、藤葛）與 `衣`
（青絹、鱗、光、黄泉…），譯名保留這個區分。

#### 人格變體：用句末助詞承載語尾變化

人物情報畫面的「自我描述」是三句話組裝出來的，`MAIN.EXE 0x045a00` 起：

```
%sは%sには自信があ%s\n            代名詞 + 能力 + 語尾
またどちらかというと自分は%s\n     + 職業
今の仕事については%sに%s           + 評價 + 語尾
```

填空的三個池子：

| 池子 | 位置 | 內容 |
|---|---|---|
| 第一人稱 | `0x053342` 起 | `自分`→吾、`私`→我、`おれ`→老子、`あたし`→小女 |
| 能力 | `0x053356` 起 | 力／知力／敏捷度／指導力／靈巧度／運 |
| 語尾 | `0x053378` 起 | `る`→也、`ります`→也、`るぜ`→哩、`るよ`→呀 |

**語尾一定要譯。** 它會直接接在譯好的句子後面，不譯就會出現
「老子對敏捷度一項頗有自信るぜ」。中文沒有對應的語尾活用，
但**人格差異可以用句末助詞承載**：平述用「也」、粗率用「哩」、
柔軟用「呀」，剛好對上原文四種人格。

第一人稱要**避開與句型用字重複**：`自分` 原本譯「自身」，
撞上句型裡的「對自身%s」會變成「自身對自身敏捷度…」，
所以改成「吾」，與 `私`→「我」分開。

#### 字串內嵌的 \n 會被 NUL 截掉

`0x045a00` 的字串是 21 bytes，第 21 個 byte 是 `\n`；
`0x045a16` 是一整條 47 bytes、中間夾一個 `\n` 的字串。
`patch.py` 的規則是「譯文長度等於 `max_bytes` 時不補 NUL，否則補」——
所以譯文只要比上限短，補上的 NUL 就會把後面的 `\n` 切掉，三句黏成一行。

**通則：若 `offset + max_bytes` 那個位元組不是 NUL，譯文長度必須剛好等於
`max_bytes`。** 否則補上的 NUL 會把同一條字串的後半截掉。全專案有 71 筆屬於
這種「字串中段」的條目，漏掉這條規則時整句確認提示（`よろしいですか？`）、
事件後續說明、術法清單的縮排全部不會顯示。

補滿的方式二選一：

- **後面接 `\n`** —— 補半形空白即可，換行前看不見。
- **後面接 ESC 色碼（`0x1b`）** —— 補空白會在句中留下可見空隙，要改寫成
  剛好等長的中文（`生産不足` 8 bytes → `生産量尚且不充足` 16 bytes）。

稽核腳本：

```python
if d[offset + max_bytes] != 0 and len(zh.encode('cp932')) != max_bytes:
    print('這筆會截斷後半')
```

## 用語統一

同一個概念在不同畫面重複出現時，用字必須一致，否則玩家會以為是兩件事：

| 日文 | 統一譯法 | 不要用 |
|---|---|---|
| 〜しますか？ | 〜乎？ | 〜嗎？（缺字） |
| よろしいですか？ | 如此可否？（前有敘述時接在逗號後：`將予以變更，如此可否？`） | 確定嗎？／是否確定？ |
| 選択してください | 請選擇 | 請選択（`擇` 在字庫內，用繁體） |
| 外に出る（指令） | 離開 | 往外而出（拗口，放在指令選單也不合語境）；劇情裡依上下文譯「出門」「出來」等 |
| すばやさ | 敏捷度 | 速度／敏捷 |
| 器用さ | 靈巧度 | 器用度（中文不成詞，字面像「器具之用」） |
| 仲間 | 同伴 | 夥伴（`夥` 缺） |
| ディスク | 磁片 | 磁碟 |
| 宝物一覧 | 寶物一覽 | 寶物一覧 |
| ドライブ | 磁片機 | 磁碟機／驅動器 |
| 道具 | 道具 | 物品（`所持品` 才譯物品） |
| データ | 資料 | 數據 |
| エラー | 錯誤 | 異常 |
| 最初からゲームをする | 開始新遊戲 | 從頭開始 |
| 途中からゲームをする | 繼續遊戲 | 從中途繼續 |
| はい／いいえ（劇情對話的是非題，`0x049e04`） | 是／否 | 可／否（題目五花八門，「這是真的麼？」答「可」不通） |
| はい／いいえ（系統確認框按鈕，`0x04511c`） | 可／否 | 是／否（題目固定是「如此可否？」，按鈕要能直接回答它） |
| レベル | 等級 | 等級值／LV |
| 達（複數詞尾） | 群 | 達（`%s達` → `%s群`） |
| 価値 | 價値 | 価値（`價` 在字庫內） |
| 逃げる | 逃走 | 逃跑（`跑` 缺） |
| 調べる | 察看 | 調査（與同畫面的 `調　査` 撞） |
| 漁労 | 漁業 | 漁撈（`撈` 缺） |
| 厳冬／猛暑 | 嚴冬／酷暑 | 嚴冬／猛暑 |
| 防御（力） | 防禦（力） | 防御（照抄日文字形；`禦` 在字庫內） |

## 格式限制

- **每則訊息上限 70 bytes**（全形字 2 bytes、控制碼 1 byte）。
- **控制碼必須原樣保留**，連順序都不能變。`tools/event.py verify` 會比對
  原文與譯文的 ASCII 序列，不符就擋下。

| 碼 | 作用 |
|---|---|
| `G` | 換行 |
| `W` | 等待輸入 |
| `N` / `X` | 接在 `G` 後，換頁／清窗 |
| `S` | 敘述模式（出現在訊息開頭） |
| `U` | 主角名變數 |
| `Y` | 是／否選項 |
